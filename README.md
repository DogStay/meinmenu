# TFL — главное меню DayZ

Клиентский мод: главное меню сервера **THE FIRST LINE | MILITARY RP** по дизайн-хендоффу
(`docs/DESIGN_HANDOFF.md`, экраны **01 MAIN MENU / id 5a** и **02 MAIN MENU HOVER / id 5b**).

Ванильное меню не переписывается: `super.Init()` отрабатывает как обычно (логика профиля,
персонажа, серверов жива), после чего его виджеты скрываются, а поверх ложится наш layout.
Если layout не загрузится — ванильное меню возвращается на место, чёрного экрана не будет.

## Структура

```
TFL/
  $PBOPREFIX$                     TFL
  config.cpp                      CfgPatches + CfgMods (missionScriptModule)
  GUI/Layouts/main_menu.layout    вся разметка меню
  GUI/textures/                   сюда кладутся .paa
  GUI/textures/_source/           исходный PNG фона (в PBO не нужен)
  Scripts/5_Mission/TFL/
    TFLTheme.c        design tokens + цветовой lerp
    TFLMenuConfig.c   JSON-конфиг в $profile:TFL/menu_config.json
    TFLMenuButton.c   5 состояний кнопки (NORMAL/HOVER/PRESSED/DISABLED/ACTIVE)
    TFLTooltip.c      tooltip 340×110: задержка 400 ms, fade 120 ms
    TFLMainMenu.c     modded class MainMenu — сборка, ввод, анимации
tools/                pack_pbo.py, list_pbo.py, sha256_file.py (из WorkKit)
```

## Настройка сервера

Файл `$profile:TFL/menu_config.json` создаётся с дефолтами при первом запуске.
Правится без пересборки PBO:

```json
{
  "ServerName": "THE FIRST LINE | MILITARY RP",
  "ServerIP": "203.0.113.10",
  "ServerPort": 2302,
  "ServerPassword": "",
  "DiscordURL": "https://discord.gg/...",
  "WebsiteURL": "https://...",
  "StatusLine": "THE FIRST LINE | MILITARY RP  ·  CHERNARUS",
  "VersionLabel": "1.0.0"
}
```

**ИГРАТЬ** делает прямой коннект на этот адрес. Пока `ServerIP` дефолтный (`127.0.0.1`) —
кнопка открывает обычный браузер серверов, чтобы меню было рабочим «из коробки».

## Сборка

1. **Текстура фона.** `TFL/GUI/textures/_source/mainmenu_background.png` → PAA:
   открыть в **TexView 2** и сохранить как `TFL/GUI/textures/mainmenu_background.paa`
   (или `ImageToPAA.exe`). Кастомные энкодеры не использовать.
   Исходник — 16:9, перед конвертацией привести к степени двойки (2048×1024 или 4096×2048).
2. **PBO.** Прекомпиляция скриптов — Workbench (`Script Editor` → мод-проект на P:).
   Упаковка:
   ```
   python tools/pack_pbo.py TFL @TFL/Addons/TFL.pbo TFL
   ```
3. Положить `@TFL` рядом с DayZ и запустить с `-mod=@TFL`.

Путь префикса и пути в `image0` обязаны совпадать: `$PBOPREFIX$` = `TFL`,
значит в layout — `TFL/GUI/textures/...`. Никаких `P:/`, `C:/`, `D:/`.

## Что нужно доделать руками

Это не «недоделки на потом», а три пункта, которые нельзя закрыть из текстового репозитория:

1. **Шрифты и выравнивание текста.** В `.layout` не проставлены `font` и выравнивание:
   имена шрифтовых ресурсов отличаются между билдами DayZ, а угаданное имя даёт невидимый
   текст. Открыть `main_menu.layout` в **DayZ Layout Editor**, задать узкий гротеск
   (аналог Barlow Condensed) и моноширинный для статус-бара, выставить размеры по
   типографике из хендоффа (TITLE 96, BUTTON 32, SMALL 20) и центрирование подписей кнопок.
   Геометрия, цвета и иерархия виджетов уже расставлены — трогать их не нужно.
2. **PAA-ассеты.** Сейчас панели, границы и марки собраны из `PanelWidget` с цветами из
   токенов — это точные цвета, но не 9-patch. По ассет-листу (карточка 8d, 52 файла)
   границы и кнопки заменяются на 9-patch PAA + StatePAA; логика состояний в
   `TFLMenuButton` уже разведена по слотам `border` / `fill` / `mark` / `label`.
   Иконки DISCORD / WEBSITE — сейчас текстовые заглушки `DS` / `WWW`.
   Виньетка и шум 5% поверх фона тоже требуют PAA и пока не реализованы;
   нижний градиент собран из 7 полос вместо настоящего градиента.
3. **Проверить имя метода прямого коннекта.** `g_Game.ConnectFromServerBrowser(...)` в
   `TFLMainMenu.TFLPlay()` — сигнатура менялась между билдами DayZ. Сверить с
   `scripts/5_Mission/gui/ServerBrowser` из скриптов текущей версии игры.

## Отклонения от хендоффа (осознанные)

- **Вертикальная раскладка низа.** В спеке `action_bar` одновременно «отступ снизу 80»,
  `status_bar` «отступ снизу 21» и «зазор до ленты 24» — три условия не сходятся
  (80 + 176 + 24 + 68 > 1080 снизу). Взята привязка к низу экрана:
  status_bar 21 от низа, зазор 24, лента выше → `action_bar.y = 791`.
  Если правильнее «80 снизу» — поменять `position` у `tfl_action_bar` в layout.
- **Ширина вторичных кнопок 240 вместо 260.** С 260 лента переполняется на 67px:
  `36 + 370 + 24 + 3×(260+24) + 1 + 24 + 2×(96+24) + 228 + 36 > 1744`.
  При 240 всё встаёт с зазором 17px до правого края.
- **ВЫХОД** прижат вправо жёсткой координатой (в layout нет `margin-left:auto`).
